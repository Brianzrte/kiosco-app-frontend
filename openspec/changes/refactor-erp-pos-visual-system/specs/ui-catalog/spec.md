## ADDED Requirements

### Requirement: Catalog workspace hierarchy

Product and category management SHALL use the shared administrative workspace
hierarchy: context and permitted primary action first, filtering controls next,
and a dominant readable data region. Product identity, price, category and
active status SHALL remain directly scannable in the list; category color SHALL
remain a labelled reinforcement rather than the only identity signal.

#### Scenario: Product list remains efficient after visual refactor
- **WHEN** an authorized user opens the product list
- **THEN** they can identify the page, reach the create action, apply existing
  filters and compare each product's required fields without decorative cards
  replacing the list
