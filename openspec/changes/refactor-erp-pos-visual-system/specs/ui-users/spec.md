## ADDED Requirements

### Requirement: User administration workspace hierarchy

User listing, detail and forms SHALL use the shared administrative workspace
hierarchy while retaining role set, active state, creation date and permitted
actions as readable information. Inactive status and role differences SHALL be
communicated with labelled content in addition to visual emphasis.

#### Scenario: Admin can scan account state
- **WHEN** an Admin opens the users list
- **THEN** they can identify a user's roles and active/inactive state from text
  and badges in the refactored data region
